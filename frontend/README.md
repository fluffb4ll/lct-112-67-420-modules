# Тренажёр оператора ДДС (АРМ-112) — фронтенд

Учебное ПО для подготовки диспетчеров ДДС города Москвы с использованием ИИ (ЛЦТ 2026, задача ДГОЧСиПБ / ГБУ «Система 112»).

Обучающийся работает в копии интерфейса АРМ-112, поверх которой лежит учебный слой: нормативы, подсказки ИИ, режим «делай как я», звонок руководителю через эмулятор VoIP и разбор после каждой карточки. Отдельно есть кабинеты обучающегося, преподавателя и администратора.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # сборка в dist/ — статика, работает в закрытом контуре без интернета
```

Шрифты и все ресурсы бандлятся локально, внешних CDN нет.

## Подключение к бэкенду

Фронт шлёт запросы на `/api/…`. В разработке Vite проксирует их на бэкенд. По умолчанию это Raspberry Pi бэкендера в сети Tailscale — `http://100.116.127.113:8080` (там же имя `shitshow.tail3143a3.ts.net`), для доступа нужно быть подключённым к Tailscale. Другой адрес задаётся в файле `.env.local` в корне проекта:

```
VITE_API_TARGET=http://localhost:8080
```

**Вход:** `POST /api/auth/login` с телом `{"username": "...", "password": "..."}`. Ответ — `UserInfoDto` (типы в `src/api/auth.ts`), токен бэкенд кладёт в httpOnly-куку `AUTH_TOKEN`. Выход — `GET /api/auth/logout`. Если любой запрос вернул 401, сессия сбрасывается и открывается вход.

Кука стоит с флагом `Secure`, поэтому в разработке открывайте фронт по `http://localhost:5173`, а не по IP — иначе браузер её не сохранит.

Роль из `user.role` определяет раздел интерфейса (`roleIdFor` в `src/api/auth.ts`): `ROLE_ADMIN` → администратор.

## Сборка контейнера

```bash
docker build -t dds-frontend .
docker run -p 8081:80 -e BACKEND_URL=http://backend:8080 dds-frontend
```

Внутри контейнера Vite собирает статику, nginx её раздаёт и проксирует `/api` на `BACKEND_URL`
(адрес указывается **без слеша на конце**). Фронт и бэк должны отвечать на одном адресе:
кука `AUTH_TOKEN` помечена `httpOnly` и `SameSite=Lax`, при обращении напрямую на другой порт
браузер её не приложит. Наружу достаточно открыть только контейнер фронта.

Пример общего `compose` (фронт, бэк, база) — в [docker/compose.example.yml](docker/compose.example.yml).
Под Raspberry Pi: `docker buildx build --platform linux/arm64 -t dds-frontend .`

⚠️ Кука входа выставляется с флагом `Secure`, поэтому стенд должен работать по HTTPS.
По `http://<ip>` вход пройдёт, но следующий запрос вернёт 401. Исключение — `localhost`.

## Что пока на заглушках

На сервере уже работают вход, выход, создание, изменение и удаление пользователей (`src/api/admin.ts`, экран «Пользователи»). Остальное работает на локальных данных в `localStorage` (`src/api/db.ts`, `src/api/index.ts`) и переводится на API по мере появления эндпоинтов — список в `docs/backend-api.md`.

## Структура

```
src/
  app/        роутинг (hash, как в реальном АРМ: #/arm/incident/<номер>), хуки
  auth/       страница входа «112 ВХОД В СИСТЕМУ»
  arm/        эмулятор АРМ-112: шапка ДДС, журнал, карточка, панель служб, форма статуса
  training/   учебный слой: полоса нормативов, софтфон (VoIP), вводные и подсказки,
              «делай как я», разбор карточки
  cabinet/    кабинеты: student/, teacher/, admin/
  domain/     доменная модель и логика без UI:
              types.ts        — контракт данных (Incident / Scenario / Attempt …)
              statusMachine   — порядок статусов реагирования (Памятка, стр. 25)
              evaluate.ts     — первичная оценка отработки карточки
              skills.ts       — модель подготовленности (Эло) и прогноз успеха
              analytics.ts    — отчёты, тепловая карта ошибок, калибровка прогноза
              text.ts         — проверки ручного ввода, скорость набора
  api/        мок бэкенда: db.ts (хранилище), index.ts (операции + аудит),
              tutor.ts (ответы руководителя, подсказки, коррекция), generator.ts (генерация сценариев)
  data/       службы ДДС, стартовый банк сценариев, демо-данные, classifier.json
  ui/         примитивы кабинетов и графики (SVG, без библиотек)
tools/classifier_to_json.py   конвертация классификатора заказчика (xlsx) в JSON
```

## Для бэкенда

- **Контракт данных** описан в `src/domain/types.ts`.
- **Операции** перечислены в `src/api/index.ts`, там же в комментарии будущие REST-эндпоинты. Для перехода на сервер нужно заменить реализацию `src/api`, компоненты менять не придётся.
- **Карточка и эталон разделены.** `Incident` — это то, что видит АРМ. `Scenario.expected` (эталон) обучающемуся не отдаётся.
- **Попытка — это поток событий** (`Attempt.events`): открытие, статусы, звонки, вводные, подсказки. Из него считаются нормативы (30 с на открытие, 3 мин на отработку), скорость набора и оценка. Этот же поток служит журналом аудита.
- **Где подключаются модели.** STT/TTS/LLM входят в `src/training/voice.ts` (голосовой канал) и `src/api/tutor.ts` (ответы руководителя, подсказки, коррекция сценария). Сейчас там правила и браузерный синтез речи.
