Руководство администратора

Пользователи, справочники, контроль работы контура
Редакция от 20.10.2026

1. Роли в системе

Роль Что доступно
Обучающийся Занятия своей группы, рабочее место АРМ, свои результаты, справочные материалы.
Преподаватель Банк сценариев, группы, занятия, мониторинг, оценка работ, статистика.
Администратор Пользователи, справочник типов происшествий, журнал системных сбоев, настройки.

2. Пользователи

Раздел Пользователи: список с поиском и фильтрами, создание, правка, смена пароля, блокировка.

Создание

  1. Нажмите кнопку создания пользователя.
  2. Заполните: ФИО, Логин (латиница, до 16 символов), Пароль (от 8 символов, буквы и цифры), Роль, при необходимости Подразделение.
  3. Сохраните. Пользователь сможет войти сразу.

Обслуживание

  • Смена пароля. Поле «Новый пароль» в карточке пользователя.
  • Блокировка. Заблокированный не может войти, но его результаты сохраняются.
  • Перевод между группами выполняет преподаватель в своём разделе «группы».
Демонстрационные пароли. На учебном стенде логины и пароли показаны прямо на экране входа. Перед передачей системы в работу их нужно заменить.

3. Справочник типов происшествий

Раздел Типы происшествий. Это тот самый список, из которого преподаватель выбирает категорию при создании сценария: без категории карточку создать нельзя, поэтому справочник заполняется до начала занятий.

  • Код — латиницей, например LIFT или GAS.
  • Название — так его увидит преподаватель.
  • Запись можно переименовать или удалить; удаление не трогает уже созданные сценарии.

Категории стоит заводить по группам единого классификатора происшествий, с которыми работает ДДС: лифты, водоснабжение, отопление, кровля, подъезд, территория и так далее.

4. Журнал системных сбоев

Раздел Система показывает технические происшествия контура: время, важность, компонент, сообщение. Развёрнутая запись содержит стек.

  • Важность: WARN, ERROR, FATAL.
  • Компоненты: ASTERISK (телефония), AI (ИИ-контур), DB (база), HTTP (веб-слой).

Если преподаватели жалуются на генерацию или распознавание речи, начинайте проверку отсюда.

5. Состав контура

Система разворачивается одной командой docker compose up -d --build и состоит из четырёх частей.

Контейнер Назначение
db PostgreSQL: пользователи, группы, сценарии, занятия, карточки, оценки.
backend Прикладной сервер: вся работа кабинетов, выдача карточек, хранение оценок.
ai ИИ-контур: генерация текста сценариев, ответы абонента, распознавание и синтез речи, оценка карточек.
frontend Веб-интерфейс и nginx: раздаёт приложение и проксирует запросы к backend и ai.

Модели ИИ-контура лежат в отдельном томе и скачиваются один раз при первом запуске: языковая модель (GGUF для llama.cpp), распознавание речи и голоса синтеза. Дальше контур работает без сети.

5.1. Переменные, которые чаще всего нужны

Переменная Смысл
DDS_LLM_MODEL_PATH Путь к файлу языковой модели внутри контейнера. По умолчанию /models/llm/model.gguf.
DDS_LLM_MODEL_URL Откуда скачать модель при первом запуске. Задаётся, если стандартный адрес с сервера недоступен.
DDS_LLM_N_THREADS Сколько потоков процессора отдать модели. Пусто — библиотека берёт половину логических ядер. Главный рычаг, если генерация идёт слишком долго.
DDS_FETCH_MODELS Выключает докачку моделей (0) — для закрытого контура, куда веса кладут вручную.

5.2. Проверка, что ИИ-контур в порядке

На сервере:

curl -s 127.0.0.1:8090/health

  • Поле llm содержит описание модели — языковая модель подключена.
  • Поле llm равно null — модели нет. Тогда контур работает по правилам: генерация сценариев будет отдавать текст заготовки, а автоматическая оценка — только формальные проверки.

6. Типовые неполадки

Что видит пользователь Что проверить
«На сервере не подключена языковая модель» Файл модели не скачался. Проверьте /health, доступность адреса загрузки, при необходимости положите файл в том вручную и перезапустите контейнер ai.
«Модель не ответила за отведённое время» Процессору сервера не хватает скорости. Увеличьте DDS_LLM_N_THREADS, при возможности — ресурсы контейнера.
Речь не распознаётся, голос не звучит Модели распознавания и синтеза не скачались, либо контейнер ai не запущен. Фронт в этом случае переключается на браузерные средства или ввод текстом.
Вход не выполняется, страница возвращает к форме Проверьте, что куку входа принимает браузер: при работе по HTTP она должна быть без флага Secure, иначе сохраняется только на localhost.
Преподаватель не может создать сценарий Пуст справочник типов происшествий — заведите хотя бы одну категорию.

7. Эксплуатационные замечания

  • Все данные учебные и синтетические; персональные данные реальных заявителей в системе не обрабатываются.
  • Контур работает полностью внутри сети организации: внешние сервисы не требуются после первой установки.
  • Резервному копированию подлежит база данных (пользователи, сценарии, занятия и оценки). Веса моделей восстанавливаются повторной загрузкой.
  • Разделы «Роли и права», «Безопасность» и «Журнал аудита» в текущей сборке работают на демонстрационных данных: серверные методы для них ещё не выведены наружу.
Учебный комплекс подготовки диспетчеров ДДС. Данные в сценариях синтетические, совпадения с реальными адресами и людьми случайны.
